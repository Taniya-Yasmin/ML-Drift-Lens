# NSL-KDD Data Provenance

The canonical raw train/test files are the complete NSL-KDD release, not the generated development fixtures. They are kept locally under `ml/data/raw/nsl-kdd-upstream/`; the repository ignores `ml/data/raw/`, so neither raw files nor credentials are committed.

## Source and Citation

The original source is the [UNB Canadian Institute for Cybersecurity NSL-KDD page](https://www.unb.ca/cic/datasets/nsl.html). The page states that the dataset is no longer hosted there and permits redistribution or mirroring when the dataset and paper are cited. The files used here come from the public [Jehuty4949/NSL_KDD mirror](https://github.com/Jehuty4949/NSL_KDD), pinned to commit `27bbbdf5c5cccf9970b8b6037a0f19dc09c5a0a9` (commit message: “The NSL KDD Dataset”).

Required dataset citation:

> M. Tavallaee, E. Bagheri, W. Lu, and A. Ghorbani, “A Detailed Analysis of the KDD CUP 99 Data Set,” Second IEEE Symposium on Computational Intelligence for Security and Defense Applications (CISDA), 2009.

The mirror's README notes that `land`, `logged_in`, `is_host_login`, and `is_guest_login` are represented as continuous/integer values. No local transformation or subset was applied to the downloaded raw files.

## Reproducible Acquisition

From the repository root in PowerShell, download from the pinned commit into the separate upstream directory. Do not download these files into the legacy root of `ml/data/raw/`, where old synthetic fixture files may exist.

```powershell
$directory = "ml/data/raw/nsl-kdd-upstream"
New-Item -ItemType Directory -Force $directory | Out-Null
curl.exe -fL "https://raw.githubusercontent.com/Jehuty4949/NSL_KDD/27bbbdf5c5cccf9970b8b6037a0f19dc09c5a0a9/KDDTrain%2B.txt" -o "$directory/KDDTrain+.txt"
curl.exe -fL "https://raw.githubusercontent.com/Jehuty4949/NSL_KDD/27bbbdf5c5cccf9970b8b6037a0f19dc09c5a0a9/KDDTest%2B.txt" -o "$directory/KDDTest+.txt"
```

Verify SHA-256 before use:

```powershell
Get-FileHash ml/data/raw/nsl-kdd-upstream/KDDTrain+.txt -Algorithm SHA256
Get-FileHash ml/data/raw/nsl-kdd-upstream/KDDTest+.txt -Algorithm SHA256
```

## Integrity and Usage

Each record has 43 comma-separated fields: the 41 ordered model features in `contracts/nsl_kdd_data_contract.json`, the attack-type label, and difficulty metadata. Integer/count feature positions contain integral values, the 15 rate fields use two decimal places and lie in `[0, 1]`, and difficulty levels span `0` through `21`. Full-file row counts, widths, labels, value formatting, and hashes were checked after download.

`KDDTrain+.txt` is the training source. The training pipeline derives a stratified validation split from it and leaves `KDDTest+.txt` untouched for final evaluation. The two files are full source sets; no local subset is used for training. The contract excludes the label and difficulty metadata from model features.

The older `ml/data/raw/KDDTrain+.txt` and `KDDTest+.txt` files are development fixtures generated by `generate_synthetic_data.py`; they are not the NSL-KDD source. That generator now writes to `ml/data/raw/synthetic/` so it cannot overwrite the canonical input locations.
